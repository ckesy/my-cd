会画图 · 模型选图型，程序给数据

用户说「看下这个月能耗环比」「哪几台车最费电」「费用都花在哪了」，助手回一张图卡。 图里的每个数字都来自工具返回值——模型只决定「画哪种图、用哪份结果」，不参与任何计算，也不会自己编一组数。

1模型只做两件事

  • 选图型：折线（趋势）/ 横条（排名）/ 环图（构成）/ 柱线组合（双指标）。
  • 指定用哪份结果：{ source: 'q_energy', ... }。
  • 它不传任何数值—— schema 里就没有 data 字段，想编也编不进去。

2为什么不用 echarts

  • 项目既有铁律：图表统一用 svgCharts.js 手写 SVG，与报表页同一套视觉。
  • 零依赖、能跟着面板宽度用 ResizeObserver 重绘（拖宽时自动适配）。
  • 小程序端没有 DOM，降级成「表格 + 一句话结论」，不硬画。

3图卡必须带的三样

  • 时间范围：右上角，避免"这是哪天的数据"。
  • 口径/来源：底部一行小字，如「耗电量 ÷ 里程 × 100」。
  • 异常标注：峰值点打标签，不用让人自己找。

4什么时候不画图

  • 只有 1~2 个数（「昨天花了多少」）→ 直接文字，画图反而累。
  • 类别超过 12 个 → 只画 Top 10 + 「其余」。
  • 时间跨度不足 3 个点 → 退回表格。

补档 · 跳过去建，回来点刷新

草稿里每一个实体字段都能补：能从已有里选就选，「新建」一律跳到对应页面。 围栏要地图选点、货物要设计价规则、车辆要填证件 —— 这些塞进 412px 的抽屉里只会更难用。 建完切回来点一下「刷新草稿」，助手把这些名字重新对一遍，能匹配上的自动变绿。

A两类字段，两种补法

  • 主数据（围栏 / 路线 / 车辆 / 司机 / 客户 / 货物）：先给候选下拉，没有就跳转新建。
  • 普通字段（数量 / 计划时间 / 运费）：就地改，输入框在行内展开。
  • 已填的字段也留「改」，允许换车换围栏，不只是补空。

B为什么跳转而不弹窗

  • 围栏要在地图上拖半径、货物要配计价规则、车辆要录证件 —— 抽屉宽度装不下。
  • 跳过去用的是完整页面和原有校验，不会出现「助手建的数据和档案页建的不一样」。
  • 代价是多一步回来点刷新，换来的是数据规范一致。

C新建的东西落到哪张表

  • 围栏 → ele_fences　路线 → routes
  • 车辆 → vehicles　司机 → drivers
  • 客户 → customer_archives（不是 customers）
  • 货物 → cargo_archives + cargo_rules（计价）

D为什么开新标签而不是跳走

  • 跳走会销毁对话和草稿卡，回来得重说一遍 —— 那才是真割裂。
  • 新标签里建完，切回来助手一个字都没变，只是数据旧了，点刷新即可。
  • 被弹窗拦截时降级为同标签跳转，草稿暂存 sessionStorage，返回后自动恢复。

E路由对照

  • 围栏 /ele-fence/setting　路线 /route/manage
  • 车辆 /archive/vehicle　司机 /archive/driver
  • 客户 /archive/customer　货物 /archive/cargo
  • 页面顶部给一条「返回助手 · 建完记得刷新」轻提示（?from=ai 触发）。

F刷新到底做了什么

  • 拿着草稿里的原始文字（青羊工业园 / 螺纹钢 / 蜀通物流）重新跑一遍实体对齐。
  • 匹配上就换成档案值并标「刚创建」；仍没有就保持待补，不会假装成功。
  • 走 action:'redraft'，不进模型，约 200ms，不扣配额。
  • 已完成的手工修改（比如数量改成 30 吨）全部保留。

G客户 / 货物必须落档案

  • 运单只存 customer_archive_id + name、货物存 cargo_name + 计价规则，所以档案必须先存在。
  • 这就是「新建后要同步到客户档案 / 货物档案」的落点 —— 不在运单里临时存个字符串了事。
  • 只填名字没建档 → 草稿标待补，不放行。
