!
为什么「逐项提醒节点」不放在这个页面

你的原话是「每一项的提醒时间都可以自定义」。那个必须勾在证件旁边（档案的证件与保险 Tab、台账的行内编辑）， 因为一台车的商业险想提前 90 天、交强险只提前 15 天，是每车每项不同的。 这个页面只配「新建时的默认值」+ 全局时间/接收人。

全局提醒设置新建 tenant_settings 或复用 tenant_modules.config（jsonb）
逐项提醒节点vehicle_certs.remind_days（int[]）
单项开关vehicle_certs.remind_enabled
接收子账号不存人名，读取时按 vehicle_affair 权限实时判定

维度方案A 独立车务管理
优点职责清晰：档案管录入、车务管盯到期，列表页不被 12 个到期列撑爆；

消息中心的关键设计点
点做法
两类东西分开提醒事项（reminders）= 要动手处理的，有状态/可改期/可关闭；通知（notices）= 只读的（围栏、系统、审批结果）。

铃铛数字= 未读 notices + 待处理 reminders + 实时费用待办（后者仍是现算，不进库）。超过 99 显示 99+。
管理端receiver_scope='platform' 的消息进 /admin 的铃铛，且能按客户分组看。主账号看不到别人的。

E
提醒的完整闭环（这是你需求里最核心的一段）

到期检测 → 先问「是否生成提醒事项」 → 生成待办 → 三种处理方式（改期 / 取消 / 取消并更新到期日） → 更新日期后再问一次是否生成新的提醒。下面把每一步的界面都画出来。

E-1 四级状态机（快到期 / 临近 / 逾期 的定义）

状态判定条件提醒频率颜色说明
正常剩余天数 > 最大提醒节点不提醒灰 / 绿只在台账里显示到期日
快到期剩余 ≤ 任一勾选节点（90/30/15/7/3）每个节点各 1 次（09:00）琥珀 #B45309勾了 30/7/3 就是第 30、7、3 天各提醒一次

F
数据模型：证件用「子表」，不要往 vehicles 上加 18 个列

原因很简单：一车多个证件、每个证件到期日不同、每个证件提醒节点不同。 宽表要写 5 组「到期日 + 提醒天数」，将来加"年检 / 二级维护 / 罐检"就要再加两列。 子表一行一个证件，加类型只加枚举值。

F-1 三张新表

-- ① 车辆证件（一车多行，一行一个证件/一项保养）
CREATE TABLE vehicle_certs (
  id                bigserial PRIMARY KEY,
  vehicle_id        text,             -- vehicles.id
  plate             text NOT NULL,
  org               text,
  owner_account     text,             -- 租户隔离（= 主账号）
  customer_id       text,             -- ⚠️ customers.id 是整数，这里存 text

  cert_type         text NOT NULL,    -- driving|transport|jq_insurance|sy_insurance|excess_insurance|maintain
  cert_no           text,             -- 行驶证号 / 营运证号 / 保单号
  issuer            text,             -- 发证机关 / 保险公司（可空）
  start_date        date,             -- 起期
  expire_date       date,             -- 到期日（核心依据）

  remind_enabled    boolean DEFAULT true,
  remind_days       int[]   DEFAULT '{30}',   -- 90/30/15/7/3 多选

  -- 保养专用
  last_maintain_date  date,
  last_maintain_km    int,
  maintain_interval_km int DEFAULT 10000,

  remark      text,
  created_at  timestamptz DEFAULT now(),
  updated_at  timestamptz DEFAULT now(),
  UNIQUE (plate, cert_type)
);

-- ② 提醒事项（待办，要人处理）
CREATE TABLE reminders (
  id               bigserial PRIMARY KEY,
  reminder_no      text UNIQUE,        -- TX20261024-0007
  biz_type         text DEFAULT 'vehicle_cert',
  cert_id          bigint,
  cert_type        text,
  vehicle_id       text, plate text, org text,
  owner_account    text, customer_id text,

  due_date         date,
  level            text,               -- 快到期|临近|已逾期
  title            text,
  content          text,
  source           text DEFAULT 'auto',       -- auto|manual
  receiver_scope   text DEFAULT 'tenant',     -- tenant|platform
  remind_days      int[],              -- 生成时快照
  next_remind_at   timestamptz,
  snooze_until     timestamptz,        -- 「今天不再问」
  status           text DEFAULT '待处理',      -- 待处理|已处理|已忽略
  handle_action    text,               -- renew|cancel|ignore
  handled_by       text, handled_at timestamptz,
  created_at       timestamptz DEFAULT now()
);

-- ③ 消息通知（只读，围栏/系统/审批结果）
CREATE TABLE notices (
  id               bigserial PRIMARY KEY,
  type             text,               -- fence|cert|fee|system
  level            text,               -- info|warn|danger
  title            text, content text,
  link             text,               -- 点击跳转路径
  receiver_scope   text, receiver_account text,
  read_at          timestamptz,
  created_at       timestamptz DEFAULT now()
);

-- ④ vehicles 只补 4 个纯档案字段
ALTER TABLE vehicles
  ADD COLUMN engine_no          text,
  ADD COLUMN first_register_date date,
  ADD COLUMN owner_name         text,
  ADD COLUMN biz_status         text;   -- 营运|停运|报废
!
必须带的两个尾巴（不然线上必踩）

① 授权段：Web 走匿名登录（anon），新表只授控制台账号会 permission denied —— 现象是「列表能打开、一条数据没有，写入报错」。末尾必须跟 GRANT SELECT,INSERT,UPDATE,DELETE ... TO anon, authenticated; + SELECT pg_notify('pgrst','reload schema');
② customer_id / org_id 是整数，新表一律声明 text，写入前 String()，否则报 uuid 语法错。

i
接收人不要「生成时快照」，要「读取时判权限」

reminders 只存 owner_account + receiver_scope，谁能看由登录时的权限实时决定。 若把接收人 id 列表快照进去，隔天给某个子账号加了车务权限，他会看不到昨天已生成的旧提醒 —— 这种"加了权限还是收不到"的 bug 极难查。

i
定时任务只有一种正确做法

Web 前端算出来的提醒「只有在页面打开时才存在」，小程序收不到。要真提醒必须云函数定时器（cron 0 0 9 * * *）写库。 前端只做兜底补算（进页面时扫一遍，防止定时器挂了没人知道）。两个都要有。
