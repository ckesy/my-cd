## 报表「关联运单口径」设计方案 v1（新产出）

文件：`/Users/lyn/my-cd-miniprogram/报表运单关联口径_设计方案_v1.html`

需求：画布泳道4 的四个报表（车队运营报告 / 综合报表 / 能耗报告 / 驾驶行为报表）
要能「关联运单」也能「不关联运单」，做成配置项。

⭐ 核实到的关键事实（决定了方案形态）：
- **四个报表依赖方向是反的**：车队运营报告以 `waybills` 为唯一数据源（关掉=空表），
  另外三个已经/将建在 `vehicle_daily_stats` + 东风 `track/*` 上，运单是**后加维度**。
  所以不是一个开关能套住的。
- **车队运营报告 `Report.vue` 只有 9 行、驾驶行为 `OperationDriving.vue` 只有 79 行，都是占位页**；
  综合报表 1560 行、能耗报告 967 行才已实现。
- ⭐ `vehicle_daily_stats` **没有 waybill_no**，字段只有
  `vin/stat_date/plate/org/customer_id/km/fuel/rate/run_min/off_min/avg_speed/start_time/end_time`
  → 「按运单」不是 JOIN，必须新做「vin + 时间窗」切片层，这是工作量大头。

方案结论（推荐 **B 配置层 + D 页面层**）：
- **B 口径三态（主口径）**：按运单 / 自动 / 按车辆。画布节点挂 `按运单 ▾` 徽标（复用费用审批三态语言）。
- **D 双视图**：报表页顶部允许临时切「按车辆/按运单」，**切了不改配置**。
- 否掉：A 单开关（车队报告关掉即空表）、C 全局口径（车队报告无法豁免）。

技术硬约束（写进方案）：
- 能耗/里程/时长 = **连续量，按里程占比分摊**（不能按时间，怠速不耗电会算错短途）。
- 超速/急加速/怠速 = **离散事件，不可分摊**，按时间点归属，落空档记「非运单」。
- 必须显示「未匹配运单」行，否则报表合计 < 车辆总电耗，客户会质疑数据造假。
- 报表是**查询视图不是快照**（与 `reports.pay_required` 相反）：切口径后历史数字会变，
  对策是在页面/导出里写死「口径 + 生成时间」。
- 口径存 `tenant_modules.config jsonb`（给现有表加一列），不新建表 —— 节点状态和参数一次查完。
- 五层由同一口径值驱动：取数 / 筛选 / 指标列 / 下钻 / 导出；页面只问
  `hasDim('customer')`，不写 `isWaybillMode`。

## v1 被用户推翻 → v2 分层方案（⭐ 这才是最终口径）

用户澄清的业务事实（**以后一律按这个**）：
1. **能耗报告定死独立**，与运单完全无关，不存在"关联"这回事，不进流程配置。
2. **驾驶行为报表是行程（trip）维度**，不依赖运单；有运单时把多个行程聚合到一单即可。
   → **先留入口，有数据了再做**。
3. **车队运营报告 = 综合报表 ⊗ 运单**，强依赖，不是独立报表。
4. **综合报表可以完全不用运单**（纯车辆运行数据）→ 因此**独立出去当必选**，不参与业务流程配置。

结论：**「报表关联运单」这个配置项根本不需要存在**，v1 的三态口径作废。
真正决定车队运营报告存不存在的，是**「运单模块开不开」**。

新的产品分层：
- **左栏「数据底座 · 必选」**（不可拖、不可关、不进流程配置）：
  综合报表（车×日）、能耗报告（独立）、驾驶行为（行程）。
- **右侧四条泳道「可配流程」**：调度 / 执行 / 费用 / 运单报表（只剩车队运营报告）。
- 连带：**运单模块必须从 L0 降为 L1 可关**，否则"不用运单的客户"无法成立。
  右半边整体 = 可插拔的「运输业务包」→ 对应两种卖法：
  **定位监控版**（左栏 + 车辆/围栏/全图监控）vs **完整运输版**（+右栏四泳道）。

车队运营报告的实现口径：**一个页面两个 tab**（车辆口径 / 运单口径），
共用 `vehicle_daily_stats` 底座，不新建取数管线。运单关 → 只留车辆 tab。

⚠️ 东风接口现实（决定 P2/P3 边界）：`track/tripAnalysisOil` 名字叫行程分析，
但**入参是日期区间、返回区间汇总**（tripMileage/sumTravelFuel/travelSumDuration/idleDuration），
**拿不到逐行程明细**。所以现在只能做「车 + 日」粒度；逐行程要等接口，
入口留在**数据模型（trip 表）**，不要在 UI 上放一个「暂无数据」的 tab。

做法（可直接照抄到实现）：
- **蛇形主链路**：泳道内横向推进（列 1→2→3），走到头在**泳道间隙**向左回绕，
  竖段落回目标节点**正上方**，箭头朝下进入。三条回绕线都落在 x=401（列1 节点中心），
  形成一条纵向对齐的视觉轴线。
  坐标：节点 230×58，列 x = 286/568/850，行 top = 72/168/264/360；
  回绕横段 y = 143 / 239 / 335（正好在泳道带之间，不穿节点）。
- ⭐ **连线不用虚线**（用户明确否掉："一条一条的太难看了"）。改成**连续渐变 + 流光**：
  1. 外发光：`stroke="url(#flowGrad)"` 12px `opacity .22` + `feGaussianBlur 4.5`
  2. 主线：3.4px 同渐变、`opacity .78`、无 dasharray（**关键：连续**）
  3. 内芯：1px 白色 `opacity .62`，让线像通电的管
  4. 流光带：白色 3.6px `opacity .55` + `stroke-dasharray` + SMIL `<animate stroke-dashoffset>`
     沿路径扫过（**透明度必须≤.6，纯白实心会被误读成断线**）
  5. 短段（泳道内 48px 横线）用 `animateMotion` 光点，r=2.3、带光晕
- **渐变方向是垂直的**（`x1=400 y1=70 x2=400 y2=440`，`gradientUnits="userSpaceOnUse"`）：
  泳道1 蓝 `#4F8EF7` → 泳道2 紫 `#7C5CF6` → 泳道3 玫 `#B44BD8/#E0407A` → 泳道4 品牌红 `#C8102E`。
  这样每条泳道一个色相、上下自然过渡，回绕线自带跨色渐变 = 用户要的"色彩融合"。
  对角渐变试过，会偏紫且同一条线忽蓝忽红，不如垂直干净。
- 箭头用**渐变填充的实心三角**（`fill="url(#flowGrad)"`），和线同色融合；
  尺寸 13×11，太小的看不清。
- ⚠️ **只有主链路发光**，旁支（常驻任务、运单口径视图）和未开通节点一律虚线灰、不流动。
  否则客户会误以为"这个功能在跑"，光效就失去语义。
- 箭头用**实心三角**（`fill:#8E9BAC`）比 stroke 折线更清晰；光点太大会盖住箭头，
  r 不能超过 2.2。
- 泳道标题只写名字（调度/执行/费用/运单报表），说明文字挪到图例 ——
  否则长标题会被回绕竖线穿过（x=401）。

## 画布开关 → 小程序联动（方案已出）

文件：`/Users/lyn/my-cd-miniprogram/小程序模块联动_方案_v1.html`

⭐ 核对到的小程序现状（关键）：

- 但**小程序端没有任何地方读 `tenant_modules`**。四处写死：
  1. `custom-tab-bar/index.js` 的 `list`（4 项：车辆管理/任务中心/上报/我的）
  2. `components/admin-tabbar.vue` 的 `items`（5 项：概览/车辆/运单/路线/我的）

  4. 云函数完全不判模块

  vehicle-list / waybill-action / waybill-admin / waybill-detail / waybill-list / wx-notify`
  → **6 个要挂闸门**（waybill-* 四个 + report-action 按动作 + wx-notify 静默跳过）；
  login/vehicle/pick/session/upload 不挂（基础能力）。

### 三层闸门（缺一就漏）
1. **入口隐藏**（底栏/菜单不渲染）— 只挡用户体验，挡不住深链/分享/返回栈。
2. **页面闸门**（onLoad 校验 + 未开通空态）— 必须做，因为
   **`tabBar.list` 是编译期固定的，页面删不掉**（隐藏入口 ≠ 进不去）。
3. **云函数闸门**（未开通 403）— ⭐ **只有这道是真安全**，前端藏按钮挡不住 `callFunction`。
   排期上必须和开关同时上线，否则开关是假的。

### 三个坑
- **缓存时效**：modules 要缓存（60s，和云函数一致），冷启动 + onShow 超 60s 重拉，
  「我的」页放手动刷新；别为实时性把 TTL 调到 5s。
- **读失败默认值**：必须沿用 Web `modules.js` 的「读失败降级为**开启**」，
  否则会出现「Web 显示开着、小程序全关」。
- **入口 vs 权限**：第一二道是体验，第三道才是安全，验收要用开发者工具直接 callFunction 拿 403。

### 业务判断
运单模块关闭时，**司机端应拒绝登录**（提示「本车队未开通运输业务」），
而不是留「车辆+我的」两个 tab 的残缺形态；管理端可降为 3 项（概览/车辆/我的）。

## 画布双视角与配置权 v4

文件：`/Users/lyn/my-cd-miniprogram/业务流程画布_双视角权限_v4.html`

用户新增约束（2026-10-20）：
- **客户账号不能编辑/配置业务流程**；只有**管理员**进客户账号才能配置。
- 客户只能看**已开启**的流程，可在已开启节点上**调参数**，**不能开关**。

设计结论：
- 把「开关」和「调参数」拆成两个独立权限（不是合并成"能不能配置"）。
- 三档：平台管理员（全开）/ 客户主账号（只看已开+调参）/ 客户子账号（基本不进画布）。
- ⭐ **客户视角下未开通节点整个不渲染**（不是灰卡）——灰卡会变成长期的
  "我为什么不能用"，SaaS 里「看不到」是中性、「看得见不能用」是负面。

## 修复：画布页太小看不清

⭐ 根因：`.flow-canvas` 是 1240 固定宽，但 SVG 用 `width:100%`，
窗口 <1240 时浏览器等比压缩整个画布 → 12px 标题被缩到 10px，看不清。

修复（`FlowCanvas.vue`）：
- SVG 改固定像素渲染，外层加 `canvas-scaler` 包裹，用 `transform: scale(s)` 缩放，
  scaler 的宽高同步 `W*s / H*s`（否则滚动条范围不对）
- 工具条加缩放条：`−  100%  +  适应宽度`，点百分比复位 100%，范围 0.6~2
- `fitWidth()`：`clamp(max(1, avail/W))` —— **只在容器够宽时放大，绝不缩小**
- 溢出提示 `↔ 可左右拖动`：`scrollWidth > clientWidth + 4` 时显示，
  scale 变化 / resize 时重算（`nextTick`）
- `.flow-scroll` 加常驻滚动条样式（macOS 默认隐藏，不加用户不知道能滚）

验证：1090×700 窗口下 100% 渲染，字号正常，提示出现。

### 画布默认缩放 130%
`const scale = ref(1.3)`，`DEFAULT_SCALE = 1.3`（点百分比复位回 130，不是 100）。
进页面**不做 fitWidth 自适应**，窄窗口靠滚动 —— 用户明确要「大」，不要「看全」。

## ⭐ 修 bug：管理员模拟客户进入，业务流程变成只读

**现象**：平台管理员从 portal 模拟进入客户账号，业务流程页顶栏显示客户文案、
节点右侧是绿点而不是「···」、抽屉里没有「停用此模块」。

**根因**：`isFlowAdmin(u)` 只判 `u.role === 'admin'`。
模拟进入后 `currentUser` 被换成客户账号（`role='customer'`），
但 `originalUser` 里还存着 admin —— Dashboard 的 `isImpersonatingAdmin` 用的是这个组合，
而 `modules.js` 完全没考虑。

**修法**（`src/utils/modules.js`）：
```js
export const isImpersonating = () => {
  const orig = JSON.parse(localStorage.getItem('originalUser') || 'null')
  const cur  = JSON.parse(localStorage.getItem('currentUser') || 'null')
  return !!(orig?.role === 'admin' && cur?.role === 'customer')
}
export const isFlowAdmin = (u) => u?.role === 'admin' || isImpersonating()
```

⚠️ 但 `ensureModuleFlags` 里要**区分**：
- 管理员**本人** → `applyAllOn()`（要在菜单里看到所有功能）
- 管理员**模拟客户** → 走正常读取，读客户的真实配置
否则模拟进去画布全是亮的，看不出客户实际开了什么。

**顺带修**：`FlowCanvas` 的 `modOn()` 原来对管理员用 `intent[key] !== false`
（没记录也算开），导致画布"看着全开、实际客户关着"。改成统一读 `effective`。

**已验证**：模拟进入后抽屉正常显示「已开通」+「停用此模块」+ 参数表单，节点右上角是 `···`。

## 未开启卡片加红色叹号

管理员视角下卡片不变灰，靠右上角**红色圆形 `!`** 提示「这个模块没开」：

- 只 `isAdmin`（含预览客户）显示；真实客户看不到这些节点（已经移到左栏）

「开启后线自动连上」不需要额外代码：`paths` 是 computed，依赖 `visibleNodes` 和
`moduleFlags.effective`，拨开关后 `ensureModuleFlags(force)` 刷新 → 自动重算连线。

## 红叹号三处修正

1. **位置**：从绝对定位（右上角 `right:30rpx`）改成**标题行内**（`.fn-t` 里，名字前面）。
   绝对定位会跟 `···` 挤在一起，且被父级 `overflow:hidden` + border-radius 影响。
2. **预览客户视角时保留**：`v-if` 从 `isAdmin && !n.enabled` 简化成 `!n.enabled`
   （真实客户看不到这些节点，本来就不会渲染，不需要 isAdmin 兜底）。
3. **开启后连线不更新**（真 bug）：原来的 `paths` computed 虽然依赖 `visibleNodes`，
   但 SVG 里用 `<defs><path :id>` + `<use :href>` 引用，Vue 复用 DOM 时只更新 `d`，
   `<use>` 的引用不一定跟着重建。修法两层：
   - `<svg class="wires" :key="wireKey">`，`wireKey` = 所有节点 uid+enabled 拼串 → 强制重建
   - `toggleModule` 成功后**本地兜底同步**：如果 `moduleFlags.effective[key] !== next`
     （说明 force 重读没拿到最新值，可能受 RLS/缓存影响），直接用 `foldDeps` 本地重算

## 旁支虚线 + 预览隐藏叹号

### ① 感叹号：预览客户视角时隐藏
`v-if="!n.enabled && !previewClient"` —— 客户视角下不该有「未开启」的警示标记，
因为客户本来就不该知道自己缺什么（左栏「可开启」已经够了）。

### ② 旁支节点连线（常驻任务）
原来 `main: false` 的节点完全不参与连线，开了也看不出来。
现在单独拉一条**虚线**：从同一行左边最近的 main 节点右侧，连到旁支左侧。
- 数据：`paths` 里追加 `{ id:'b'+idx, d:'M x1 y H x2', dash: true }`
- 渲染：单独一层 `<g stroke-dasharray="5 4" opacity=".5" stroke-width="2.2">`
- **主链的柔光/管体/白芯/光柱/箭头全部要 `.filter(x => !x.dash)`**，
  否则虚线也会被画成粗实线（漏一个就穿帮）
- 用虚线而不是实线的原因：并进主链路会让人以为流程**必须**经过常驻任务

### 验证（截图）
- 管理员 + recurring 开：派单配载 →（浅紫虚线）→ 常驻任务
- 预览视角：三个未开启节点变灰、**红叹号全部消失**、虚线保留（常驻任务是开的）

### 子功能开关存储
`tenant_modules.config.sub = { <nodeKey>: { <featureKey>: bool } }`
- 步骤节点没有自己的 module，**子功能挂在 `waybill` 上**（`moduleKey = n.module || 'waybill'`）
- 没配过 = 全开（`sub[fk] !== false`）
- 卡片上**只显示已开启的**功能（关掉的从卡片上消失）
- 保存走 `setModuleConfig(mk, { sub })`，`CONFIG_WHITELIST` 要放行 `sub`

### 费用审批开关
不是模块表，而是 `fee_approval_configs.mode`（on/off）。
- 节点标 `special: 'audit'`，`enabled = approvalMode !== 'off'`
- 浮层里按钮写 mode，写 `fee_approval_configs` 的 upsert
- 这样和「费用审批设置」页是同一个开关，不会出现两处打架

### 浮层（替代右侧抽屉）
- `position: fixed` + **`<Teleport to="body">`**
  ⚠️ 必须 Teleport：`.content-wrapper` 有 `animate-fade-up` 的 transform，fixed 会变成相对它定位
- 坐标用卡片 `getBoundingClientRect()`，下方放不下就往上弹
- 卡片必须带 `:data-uid="n.uid"` 才能被 `querySelector` 定位（**漏了这行浮层根本不出现**）
- 滚动时直接关闭浮层（位置会错）

### 客户视角
- 「N 个模块因依赖未满足」黄条 + 降级提示条：加 `&& isAdmin`
- 未开通清单统一显示「需联系运营人员开启」（不再有「可开启」）

### ⚠️ 又一个崩溃坑
`paths` 里 `nodes[nodes.length - 1]` 在**整行没有可见节点**时是 `undefined`，
再读 `.x` 就 `Cannot read properties of undefined`。
客户视角把某一行模块全关、或 mock 全关时必现。
→ `rows.forEach` 开头加 `if (!nodes.length) return`，回绕条件也加 `&& nodes.length`。

## 小程序 H5 预览登录页"撑满整屏"的原因与修复

**不是 bug**，是 uni-app H5 的 rpx 换算问题：
- `manifest.json` 没有 `h5` 段 → rpx 按浏览器窗口宽度换算，
  1080px 宽时 1rpx ≈ 1.44px，所有字号/间距被放大 1.4 倍
- 登录页的输入框是 `width: 100%`，H5 下就撑成一条 1000px 的长带子
- **小程序真机不受影响**（rpx 按 375 换算）

修复两处：
1. `src/manifest.json` 加：
   ```json
   "h5": { "rpxCalcMaxDeviceWidth": 750, "rpxCalcBaseDeviceWidth": 375, "devServer": { "port": 5173 } }
   ```
   超过 750px 的屏幕按 750 算，1rpx = 1px，字号不再放大
2. `src/pages/login/login.vue` 末尾加 **H5 条件编译**：
   ```css
   /* #ifdef H5 */
   body, uni-page-body { background: #EDF1F6 !important; }
   .login-page { max-width: 430px !important; margin: 0 auto; box-shadow: ...; }
   /* #endif */
   ```
   收成手机宽度居中，像"移动端"而不是"网页"

⭐ `#ifdef H5` 的 CSS 不会打进小程序包，可以放心留着当预览环境。
⚠️ 改 manifest 后**必须重启 dev server**（`ctrl+c` 再 `npx uni -p h5`），
   热更新不读 manifest。端口被占时 uni 会自动顺延到 5174。

## 修：费用明细页权限被拦

## 二级菜单 hover 放大：为什么第一次没生效

加了 `scale(1.06)` 但用户说"还是不变"。两个原因都要排掉：

### ① `.el-menu--inline` 有 `overflow: hidden`
Element Plus 为了做子菜单的展开/收起动画，给内嵌的 `ul.el-menu--inline` 设了
`overflow: hidden` —— 放大 6% 溢出的部分直接被裁掉，肉眼等于没变化。
→ `:deep(.el-menu--inline) { overflow: visible !important }`

### ② 选择器优先级 / 匹配
` .sidebar-menu :deep(.el-sub-menu .el-menu-item)` 编译后是
`.sidebar-menu[data-v-xxx] .el-sub-menu .el-menu-item`，
Element Plus 自己的 `.el-menu-item` 规则可能盖住部分属性。
→ 去掉 `.sidebar-menu` 前缀、直接用 `:deep(.el-menu--inline .el-menu-item)`，
   并给 `transform` / `color` / `background-color` 加 `!important`。

### 一级为什么能看到
一级的动画作用在**图标**上（`.el-icon { transform: scale(1.15) }`），
图标在 `.el-sub-menu__title` 里，不受 `.el-menu--inline` 的 overflow 影响。
二级没有图标，只能靠整行 transform —— 所以撞上了 overflow。

## 二级 hover "生硬" → 过渡参数对齐一级

一级图标：
```css
transition: transform 0.3s cubic-bezier(0.34, 1.56, 0.64, 1), color 0.3s;
transform: scale(1.15) translateX(2px);
```

我一开始给二级写的是 `.24s` + `translateX(3px)` —— 时间更短、位移更大，
虽然曲线一样，但**参数不一致就会显得一蹦一蹦**。

改成完全对齐：`0.3s` 同曲线、`scale(1.06) translateX(2px)`（幅度略小，因为整行放大比图标放大更抢眼）。

⭐ 这类"动效不协调"的问题，解法不是调曲线，是**把时长和位移抄成一样**。

## 二级 hover "没有过程动画" 的排查与最终解法

排查顺序：
1. `overflow: hidden` 裁剪 → 已放开（`.el-menu--inline { overflow: visible }`）
2. 选择器优先级 → 已去掉 `.sidebar-menu` 前缀
3. `transition` 简写 + `!important` → 拆成 property/duration/timing-function 三个属性
4. 查过没有任何规则覆盖 transition
5. **还是像瞬跳** → 两个原因叠加：
   - 幅度太小：`scale(1.06)` 在 200px 宽的行上只差 12px，0.3s 看不出过程
   - EP 的 hover 同时改背景色，transition 偶尔不触发

**最终解法：改用 `animation`**
```css
@keyframes submenuPop {
  from { transform: none; }
  to { transform: scale(1.1) translateX(3px); }
}
:deep(.el-menu--inline .el-menu-item:hover) {
  animation: submenuPop 0.3s cubic-bezier(0.34,1.56,.64,1) forwards;
}
```
`animation` 只要选择器命中就一定会播，不受"属性是否变化"影响。
幅度提到 `1.1 / 3px`，肉眼能看出过程。

⚠️ 代价：鼠标移出是瞬回（没有反向动画）。要顺滑得再配 `transition` 在非 hover 态做还原。

## 二级菜单动画：最终撤掉

试了 4 轮（overflow 放开 → 选择器提权 → transition 拆属性 → 改 animation），
用户仍觉得"没有过程动画"，最后决定**恢复原样**，二级菜单只保留 Element Plus 默认的
hover 背景/文字变色，不加放大。

已删除：
- `@keyframes submenuPop`
- `:deep(.el-menu--inline .el-menu-item)` 的 transform/transition
- `:deep(.el-menu--inline) { overflow: visible }`
- `.is-active { transform: none }`

⭐ 以后的判断：**一级图标的 scale 好用，不代表二级整行 scale 也好用**。
整行 transform 会撞上 Element Plus 的 overflow 裁剪和 hover 规则，
投入产出比很低 —— 下次遇到同类需求，先问"要的是不是位移/变色"，别直接上 scale。

ALTER TABLE waybills ADD COLUMN IF NOT EXISTS fleet_name text;  -- 冗余，省掉每次 join

## 🐞 修：一个运单分多车时只有一个人能接

### 用户反馈
"一个运单派了 3 台车，只有一个人能接"

### 根因（两处配合）
**① `waybill-action/index.js` 的 `aggregateRowPatch`**
```js
let status = '待装车'                 // ← 默认值
if (pending === total) status = '待接单'
```
3 台车：第 1 个司机接完 → `pending=2 / total=3` → 不满足 `pending === total`
→ 落到默认值 **「待装车」**，行级状态就变了。

**② `waybill-list/index.js` 的 `buildActions(wb)`**
```js
enabled: ACTION_STATES[key].includes(status)   // 用的是行级 status
```
`accept` 只允许 `from: ['待接单']` → 行级变「待装车」后
→ **另外两个司机的「接单」按钮直接灰掉**。

### 修复
**① 聚合逻辑**：只要还有人没接，整单就停在「待接单」
```js
if (pending > 0) status = '待接单'
else if (done === total) status = '已完成'
else if (rejected === total) status = '待重新指派'
else if (done + rejected === total) status = '已完成'
else status = '待装车'
```

**② 动作判定**：`buildActions(wb, leg)` 传腿，按**我这一趟**的状态算 enabled：
```js
const status = leg ? legStatusOf(leg, wb) : String(wb.status || '').trim()
```
调用处：`...buildActions(view, leg)`（list 里已有 leg 变量）

### 验证（`/tmp/verify-leg.js` 复刻逻辑跑了一遍）
| 场景 | pending/total | 旧 | 新 |
|---|---|---|---|
| 3 车都没接 | 3/3 | 待接单 | 待接单 |
| **1 车接了** | 2/3 | **待装车** ❌ | **待接单** ✅ |
| **2 车接了** | 1/3 | **待装车** ❌ | **待接单** ✅ |
| 3 车都接了 | 0/3 | 待装车 | 待装车 |

⚠️ **改的是云函数，必须重新部署 `waybill-action` + `waybill-list` 才生效。**
