## 上传图片失败（Failed to fetch）= COS 桶没配 CORS

- 现象：维修台账「新增维修记录」传照片报「上传失败: Failed to fetch」。
- 实测（`uploadPhoto` 网关 `…-1447716425.ap-shanghai.app.tcloudbase.com/uploadPhoto`）：
  - `signPut` 正常，回预签名 URL（桶 `wuxian-fleet-1447716425`，region `ap-shanghai`）；函数自身 CORS 正常（回显 Origin）。
  - 对 COS 的 **OPTIONS 预检 → 403 且无任何 `access-control-*` 头**（线上域名 / localhost:5173 / example.com 三种 Origin 都一样）。
  - **绕过浏览器直接 PUT → 200**（签名与桶权限都正常）。
  - GET 返回 200 但同样没有 ACAO —— 图片能显示是因为 `<img>` 走 GET 不需要跨域。
- 结论：**桶 CORS 完全没配**。小程序能传是因为 `wx.request` 不受 CORS 约束（2026-10-20 只有小程序验证通过过）。
- ⚠️ 纯前端无解：PUT 必触发预检；`no-cors` 模式不允许 PUT。只能配桶 CORS，或改成云函数服务端写 COS。
- 需在 COS 控制台给 `wuxian-fleet-1447716425` 加规则：来源 `*`、方法 PUT/GET/HEAD/POST、Allow-Headers `*`、Expose-Headers `ETag`、Max-Age 600。
- 代码侧已加固（`src/utils/cos.js`）：`putToCos` 捕获 TypeError → 抛可读文案（指明桶 + 控制台路径）；`post()` 失败提示签名服务不可达；`RecordDrawer` 长错误 12s + 可关闭。
- 影响面：`putToCos` 只有两处 —— 维修台账 `RecordDrawer`、付款凭证 `PaymentDialog`。

## 车辆运行大屏（FleetScreen）：地图默认全览 + 首屏提速

诉求：① 进大屏地图默认显示全部车辆；② 查询太慢。

- 根因：`initMap` 固定 `center:[112.3,37.6] / zoom:7`，**从未调 setFitView**；定位逐台 HTTP 且 `await` 整批跑完才一次性 `renderMarkers`，30 台车 6 并发 → 数秒空白；今日里程还要等定位跑完才起跑。
- 改法（`src/views/screen/FleetScreen.vue` + `src/utils/screenData.js`）：
  - 地图 `setFitView(markers, false, [96,72,84,72], 13)`，**只在首轮定位跑完（rtLoadedOnce）后 fit 一次**（避免底图 complete 早到、按三五台车框出一小块）；`didFit` 保证后续 30s 刷新不抢用户视野；左下角加「全览」按钮强制复位。
  - 打点改 `markerByPlate` 复用 + `upsertMarker`（setPosition/setContent），不再 remove/add 全量，30s 刷新无闪烁；`flushMarkers` 解决地图未就绪时先攒点。
  - `pullRealtime` 并发 6→12，新增 `onVehicle(plate, rt, v, failed)` 逐台回调 → 边到边画点；`failed` 区分「请求失败（保留上轮，别闪没）」与「无数据（掉离线）」。
  - 车辆清单 5 分钟缓存（ensureVehicles），30s 刷新只刷定位。
  - 今日里程与定位**并行**（不再串行），`pullTodayMileage` 并发 5→8、判定放宽（rt 未知也先算）、`fetchDayMileage` 超时 20s→12s 且失败结果也落缓存。
  - `onMounted` 里 loadAlertCfg/loadBehavior/loadDaily、initMap、取数全部并行，不再串行 await。
