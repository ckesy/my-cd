## 「同步数据」按钮报 Failed to fetch 的原因

- 实测网关 `.../opStatsSync` 返回 **404 INVALID_PATH**，且响应里**没有 CORS 头**，
  所以浏览器只能抛 `Failed to fetch`（读不到 404 body）——即云函数还没部署/未开 HTTP 访问。
- 处理：`triggerSync` 里 catch 网络异常 → 换成「同步服务不可达：云函数还没部署或未开启 HTTP 访问服务」，
  页面用 warning 而非 error 提示。
- 另提供免部署方案 `scripts/sync-op-stats.mjs`：
  `CLOUDBASE_APIKEY=xxx node scripts/sync-op-stats.mjs --days=7`
  直接连 CloudBase RDB 写库（已装 @cloudbase/node-sdk 为 devDependency）。

## opStatsSync 云函数报 FUNCTION_INVOCATION_FAILED 的处理

- 症状：开了 HTTP 访问后，网关返回 400 `FUNCTIONS_INVOCATION_FAILED`（CORS 已正常）。
- 根因排查方向：① 云函数 Node 16 及以下**没有全局 fetch**；
  ② 只传了 index.js/package.json、没装 `@cloudbase/node-sdk`。
- 已改：`fetch` → `https.request` 封装；`require('@cloudbase/node-sdk')` 用 try/catch
  包住，缺依赖时 return 明确文案；整个 main 包 try/catch，异常也 return（否则网关只给
  INVOCATION_FAILED，看不到原因）。
- 加了 GET 健康检查：`GET /opStatsSync` 返回 { service, node, hasApiKey }，
  配完环境变量可以先 GET 一下确认 hasApiKey=true。

## 脚本报 Invalid character in header content ["Authorization"]

- 原因：`CLOUDBASE_APIKEY` 传的是占位符/带中文或空格的值（用户直接把文档里的「你的key」粘进命令），
  SDK 把中文塞进 Authorization 头 → Node 直接抛 TypeError。
- `scripts/sync-op-stats.mjs` 已加前置校验：去空白/去引号 → 正则 `^[\x21-\x7e]+$` 校验
  → 不合法时打印打码后的值和长度并退出；运行时会打印 `Key：abcd***wxyz（长度 N）` 便于核对。
- 也支持 `--key=xxx` 传参，避免 shell 引号问题。

## opStatsSync 真因：env 传了 Symbol（+ 前端把失败当成功）

- 函数日志真相：`TypeError: Cannot convert a Symbol value to a string`
  at node-sdk `getGatewayUrl` —— 因为 `tcb.init({ env: tcb.SYMBOL_DEFAULT_ENV })`，
  一旦同时配了 `accessKey`（API Key 模式），SDK 要把 env 拼进网关 URL，Symbol 无法转字符串。
  ✅ 修法：`env: process.env.TCB_ENV || '<显式环境ID>'`。
- 第二个问题：函数内部异常时网关仍返回 **HTTP 200 + {ok:false,error}**，
  前端只判断 res.ok，于是把失败显示成「同步完成」。
  ✅ `triggerSync` 增加 `data.ok === false` 判断并抛出 error。
- 云函数超时默认可能只有 3~20s：补 2 天 × 40 台要 15~20s，需把函数超时调到 **60s+**。

## opStatsSync 第三关：Invalid schema

- 报错 `读 vehicles 失败：Invalid schema: <envId>`。
- 根因在 node-sdk 源码 `dist/cloudbase.js`：
  `const { instance='default', database = envId } = options || {}`，
  然后把 database 作为 `Accept-Profile` / `Content-Profile`（PostgREST 的 schema）发出去。
  不传参时 schema = envId → 网关拒绝。
- ✅ 修法：`app.rdb({ database: process.env.RDB_SCHEMA || 'public' })`（函数和本地脚本都改了）。
- 教训：CloudBase Web SDK 直接 `app.rdb()` 能用，但 **node-sdk 必须显式给 schema**。

## opStatsSync 第四关：时区 + 日期时间解析（云函数跑在 UTC）

- 报错 `RangeError: Invalid time value at Date.toISOString`：
  `parseDay('2026-10-16 06:34:06')` 会在后面再拼 ` 00:00:00` → Invalid Date。
  ✅ 新增 `parseDT()`：把 "YYYY-MM-DD HH:mm:ss" 按 **+08:00** 解析再 toISOString。
- 同时发现云函数环境是 **UTC**：`new Date(Date.now()-86400000)` 算出来是「前天」，
  所以之前的 range 是 ["2026-10-16","2026-10-16"] 而不是 10-17。
  ✅ 统一改成 `todayBJ()`（+8h 取日期）+ `addDays/diffDays` 用 UTC 锚点做纯日期运算。
- ⚠️ 本机工具输出会把某些日期串显示成 `2026-10-17`（渲染层的怪问题），
  排查时不要被这个吓到，以逻辑和接口返回为准。

- `POST {"days":7}` → `{ok:true, tasks:190, written:190, empty:21, failed:0, 19.5s}`

## 工作台三个问题的修复

## 矩阵"没有色块"的两个原因

1. **CSS 覆盖**：OpView 里 `.mx-cell { background:#f8fafc }` 写在 `.lv1..lv5` 之后，
   同权重（都是 1 个类）→ 后写的赢，色阶被默认底色盖掉。

2. **阈值是绝对值**：205/220/235 是按早期那批车（216 左右）定的，
   现在的车队电耗 160~190 → 全部落进最浅档，看起来就是白的。
   ✅ 改成**按当前数据分位**：`quantiles(arr,[.2,.4,.6,.8])` + `levelOf()`，
   日历按当月电耗分位、矩阵按里程分位（与说明"越深跑得越多"一致）。
3. 矩阵里区间内完全没数据的车不再占行（否则半屏空白像坏了）。
- 教训：色阶一律用相对分位，别写死业务阈值；设置底色的类不要写在色阶后面。

## 悬浮气泡 / 象限补全 / 固定列视觉

- 悬浮：原生 title 不可控（延迟 1s、样式丑），改成 teleport 到 body 的深色气泡 `.op-tip`，
  `mouseenter` 显示 + `mousemove` 跟随 + 边界钳制；矩阵/排行/剖面/待办/节律/象限/日历都接了。
- 象限：原来 svg 漏了 `class="quad-svg"`（导致 CSS 的 height:100% 没生效、图不走容器高度）；
  补了网格线、X/Y 刻度、轴标题、四象限台数；`minY = Math.min(...ys, 0) - 4` 会把下限永远压到 -4，
  改成 `Math.max(0, min-6)`。

  已给固定列表头加深底色、固定区边界画实线；数值列再收窄（130→112 等），中间能多露 2 列。
- 教训：原生 title 不适合重要信息提示；SVG 组件别忘加 class 否则尺寸规则失效。
