### 关键设计决策（后续改代码要遵守）

- **「节点完成时间」= 下一个节点的进入时间**。线性流转链没有独立的「完成」事件。
- **装货地/卸货地存的是围栏名称**（不是地址）。地图取坐标先按 `name` 反查
  `ele_fences.center`；只有文本里出现 省市区路街道号 等字样才走地理编码，
  否则围栏别名会被编码到无关坐标。
- **只有单车牌记录才画车辆实时位置**：`waybills.vehicle` 在多指派时会退化成
  `多种` / `N辆`，必须优先解析 `assignments` 里 `method === 'vehicle'` 的 target。
- **常驻任务次数闸门的权威口径**：统计同 `recurring_group_no` 下
  「`accept_time` 非空 或 状态已进入执行中」的运单数，**不读** `recurring_accepted_count`
  （该字段仅作展示与兜底）。
- **一个常驻任务的多条运输记录 = 多条 `waybills` 行**，靠 `recurring_group_no` 关联。
  下一趟目前复用「创建相同运单」链路（cloneData 会带上 groupNo），未做自动排期生成。
- 轨迹当前画的是**高德驾车规划路线**，不是真实行驶轨迹（东风历史轨迹接口未开 HTTP 网关）。

### 关键结论（新增）

- **运单状态枚举现在是 9 个**：待接单 / 待重新指派 / 待装车 / 装车中 / 装车完成 /
  已发车 / **已到达** / 已完成 / 已取消。`装车中` 是历史遗留，新流程不再产生。
- **运输节点模式**（`waybills.transport_mode`）决定司机端动作链：
  极简 = 接单 → 完成运单；详细 = 接单 → 装车完成 → 确认发车 → 确认到达 → 完成运单。
- **打卡点与围栏的对应**：装车完成 → **装货地**围栏；确认到达 → **卸货地**围栏。
  校验位置来自**车辆最后一次上报**（不是手机定位），所以车辆熄火/离线时可能误判。
- **围栏几何**：`ele_fences.shape` = circle（center+radius）/ polygon（points 射线法）/
  polyline（points+bufferradius）/ district（无法本地判定，放行 + warn）。
- **东风历史轨迹接口**：`/api/admin/openapi/api/track/history`，
  `carId` = **完整 VIN**，`beginTime` = 接单时间，成功码 `code === 1`，
  返回 `{longitude, latitude, velocity, direction, sendTime, mileage}`。
  该接口**回显任意 Origin**（CORS 等于全开），前端可直连；token 走
  `import.meta.env.VITE_DONGFENG_TOKEN` 覆盖，以后再挪到云函数。

### 关键结论（新增）

- **进度口径**（已与用户确认，勿改）：
  已行驶 = **从「确认发车」起算**的轨迹点累加（不从接单起算，否则场内挪车会虚高）；
  剩余里程 = `plan_distance − 已行驶`（<0 按 0 计并标「已超规划里程」）；
  剩余时间 = `plan_duration × 剩余比例`；ETA = 现在 + 剩余时间。
  定位停更 > 30 分钟 → `stale`，**不展示 ETA**。
- **规划里程在「发布时」算一次落库**，不进刷新链路（刷新只拉东风轨迹）。
- **同车/同司机并发规则**：同一车牌或同一司机在同一 `owner_account` 范围内，
  只能有一条未结束的运输记录（未结束 = 不属于 已完成/已取消/待重新指派）。
  校验查询失败时**放行**，不因校验故障挡住司机。
- **常驻任务的周期甘特按天刻度**，"过去没跑"必须与"未来未开始"视觉区分（斜纹缺口）。
- 常驻运单**不显示地图**；普通运单保留地图 + 节点时间轴，并在上方加进度双条。
