状态怎么变

  1. 一条运单在同一时刻只有一个状态，共 9 个：待接单 / 待重新指派 / 待装车 / 装车中 / 装车完成 / 已发车 / 已到达 / 已完成 / 已取消。
  2. 正常路径：待接单 → 待装车 → 装车完成 → 已发车 → 已到达 → 已完成。
  3. 「装车中」是早期遗留状态，正常流程不再产生，只在看老数据时会遇到。
  4. 完成和取消都是终态，不能再往回改，只能补录费用。

谁能动这条单

  1. 只有被派到的人能接单和上报节点；别人在任务清单里根本看不到。
  2. 派给车队时，该车队及其下级车队的司机都能看到、都能抢，谁先接算谁的。
  3. 已被同事接走的单，10 分钟内还会显示但标注"已被接走"，不告诉是谁接的。
  4. 调度只能在「待接单 / 待重新指派」时改派，已接单的不能直接换人。
  5. 取消运单需要说明原因，已完成的运单不能取消。

一车一人只能干一件事

  1. 同一辆车、同一个司机，同一时间只能有一条没跑完的运单。
  2. 「没跑完」= 待装车 / 装车中 / 装车完成 / 已发车 / 已到达。
  3. 「待接单」还不算占用 —— 因为还没接，可以改派给别人。
  4. 司机拒单后，这辆车立刻释放，别的单可以派给他。
  5. 这条规矩在建单时不拦，在司机接单那一刻才拦，提示"该车还有未结束的运输记录"。

打卡（到场证明）

  1. 「装车完成」要在装货地围栏里点，「确认到达」要在卸货地围栏里点。
  2. 判断依据是车辆的定位，不是手机定位 —— 人到了车没到不算。
  3. 一单派了多辆车时，不做围栏打卡校验（无法判断是哪辆车）。
  4. 围栏画的是行政区划时，系统无法判断，直接放行并留一条说明。
2

常驻任务：固定线路天天跑

一条任务管一个周期内的 N 趟，司机每趟单独接
典型场景：厂区到码头每天 4 趟、包月倒运。和普通运单的区别：普通单是一单跑一次，常驻任务是一单跑很多次，次数或时间到了自动收口。
调度（电脑端） 司机（小程序）
1
建一条常驻任务调度
照常填运单信息线路、货物、装卸地
→
打开「常驻」这条单就变成一个周期任务
→
选计算方式按时间 或 按次数
→
发布自动生成组号，状态"生效中"
按时间设开始日期和结束日期，在这段时间内可以无限接，到期自动停。
按次数设总趟数上限，例如 30 趟，跑完即止，跟日期无关。
2
司机每趟「接一趟」司机不是接整条任务，是接其中一趟
现在能不能接这趟？
可以任务在有效期内、额度没用完、任务没暂停 → 接单成功，生成一趟新的运单，之后按普通运单流程跑。
不可以提示「还没到开始时间 / 已过有效期 / 已暂停 / 次数已用尽（已用 28/30）」。
抢慢了额度是所有司机共享的，同时有两个人接，后到的提示「额度刚好被别人用完，请刷新」。
3
每趟照常跑完司机
接一趟生成一趟运单
→
装货 → 发车 → 到达同普通运单
→
完成这一趟累计已完成趟数
注意：常驻的每一趟都没有计划时间（因为是临时排的），所以在运单详情里不会显示"计划 vs 实际"的对比，只有实际发生的时间。
4
任务怎么收口系统 / 调度
自动结束按次数：次数用满 且 最后一趟已跑完 → 整条任务置「已结束」。按时间：过了结束日期 → 置「已结束」。
手动操作调度可「暂停」「恢复」「提前结束」。只要还有一趟在跑，这三个操作都不允许，要先等那趟跑完。

列表里怎么看

  1. 一个常驻任务在运单列表里只占一行，显示"执行中"，不会因为某一趟完成就显示已完成。
  2. 点开这一行能看到它一共跑了几趟、哪趟在跑、哪趟被拒过。
  3. 司机端也是按任务展示，展开才看到自己的历次趟次。

为什么不让你随便改

  1. 常驻的趟次不能拒单 —— 拒了额度就浪费了，只能不接。
  2. 趟次不能在小程序里改派或删除，要回电脑端处理。
  3. 删除一条常驻任务 = 把它名下所有趟次一起删掉，需谨慎。
  4. 建单时不检查额度够不够、日期合不合理，这些都在司机接单那一刻才检查 —— 这样调度可以先建好，等真正开始跑再约束。
3

分车承运：一单货拆给几辆车

也叫子母车 / 多车承运，每条腿独立跑、独立结算
典型场景：30 吨货，2 辆车各拉 15 吨，一起去同一个卸货地。核心约束：拆出去的量加起来必须等于总量。
1
建单时拆量调度
指派方式选「多辆车」或「多个司机」
→
每辆车填承运量和这辆车对应的运费
→
系统核对合计必须等于货物总量
→
发布每辆车各拿到一趟
对不上合计和总量不一致时不允许发布，提示差了多少。允许 0.01 的尾差（分账时的四舍五入）。
自动平摊没手动改过的那些车，系统把「剩余量」平均分给它们，保证总量守恒。
2
每辆车各跑各的各车司机
各自接单只看到自己那一趟
→
各自装货 / 发车 / 到达各报各的节点
→
各自完成互不影响
某车拒单只有这一趟变成「待重新指派」，其他车照常跑，整单不会卡住。
3
整单什么时候算完成系统自动
全部完成所有车都完成后，整单变「已完成」。
跑完 + 拒单剩下的车都完成、其余都是拒单，也算整单收尾 —— 因为不可能再等了。
还有在跑只要有一辆车没结束，整单就显示"执行中"。

什么算分车承运

  1. 必须同时满足：不是常驻任务 + 拆成 2 趟以上 + 每趟派的是司机或车辆。
  2. 只要其中有一趟是派给车队，整单就不按分车承运处理，退回普通单逻辑。
  3. 分车承运的单，车牌和司机在列表里统一显示"多种"，要看明细得展开。

占用与可见性

  1. 判断"车有没有空"时看所有在跑的趟次；判断"司机有没有空"时只看他自己那一趟，避免两个司机互相挡住。
  2. 每个司机只能看到自己那一趟，看不到别人的进度。
  3. 详情页可以按车切换，一辆车一条时间轴。
  4. 费用也按趟报、按趟审，最后一趟车的费用不影响其他车。
4

派单、改派与拒单

三种派法，三种后果，别混着用
A
三种派单方式，区别在哪调度
派司机指定到人。@张三 接了就完事。适合固定司机。拒单由他自己拒。
派车辆指定到车。谁开这辆车谁就能接（车绑定了哪个司机就谁来）。适合车比人固定的场景。
派车队指定到机构。该车队及其下级车队的所有司机都能看到、都能抢，先到先得。适合运力池调度。
注意：派车队时不能拒单（因为不是派给某个人的），并且这种单不能按分车承运处理。
B
改派的规则调度
现在这条单能不能改派？
能改运单在待接单或待重新指派 → 可以换人/换车/换车队。改完状态回到「待接单」，原来那个人就看不到了。
不能改已经接了（待装车及以后）→ 不允许直接换人。要么让司机跑完，要么走取消/异常流程。
为什么改派要退回「待接单」：如果保留"待重新指派"，新司机在任务清单里根本看不到这条单 —— 退回待接单才是"重新挂出来让人接"。
C
拒单之后发生了什么司机 → 调度
司机拒单必须选原因 + 可补充说明
→
运单变「待重新指派」记录拒单次数与原因
→
调度收到提醒在列表里能看到这单卡住了
→
重新指派换人 → 回到待接单
原因选项车辆故障 / 时间冲突 / 路线不熟 / 其他。"其他"必须写明，否则提交不了。

任务清单的可见规则（司机端）

  1. 只看得到最近 90 天的单，更早的归档不展示。
  2. 「待重新指派」的单不出现在司机端 —— 那是调度要处理的。
  3. 常驻任务按"组"展示，只列自己的趟次；组长没派给自己，整组都不显示。
  4. 被同事抢走的单，10 分钟内还留着并标注"已被接走"，10 分钟后彻底消失。
  5. 管理员身份的单（没归属到具体客户）要靠"名字唯一匹配"才认领，重名时分不清就不给接，避免接错。

改派与编辑的连带影响

  1. 改派后，原来那条指派记录被整体替换，不是追加一条。
  2. 调度在电脑端"编辑运单"也会把状态打回「待接单」，等于变相重新派单。
  3. 编辑不会重算计划里程和坐标 —— 换了装卸地要重新发布或重新规划路线。
  4. 两人同时改同一条单，后保存的会失败并提示"刚被改过，请刷新"。
5

费用：从司机报账到财务打款

8 类费用，3 级审批，2 个开关控制整条链路走不走
谁发起：司机在小程序上报，调度/财务/老板在电脑端审，财务打款。前提：这趟单必须已经接单，而且确实是派给这个司机的。
司机（上报） 调度（一级审） 财务（二级审 / 打款） 老板（终审）
1
司机上报一笔费用司机
选运单只能选自己的单
→
选费用类型8 类，见下
→
填金额与说明费用类要逐笔填明细
→
上传凭证部分类型必传
→
提交进入「审核中」
钱款类费用报销、补贴、借款、违章 —— 这 4 类计入费用总额，参与统计。
单据类磅单、超时报备、回单、油卡补录 —— 这 4 类只记笔数和业务信息，不计入金额，避免总额虚高。
必传凭证的三种：磅单（要过磅照片）、超时报备（要现场照片）、违章（要处罚决定书）。其余类型可以不传，但建议传。
2
逐级审批调度 → 财务 → 老板
一级：发单人通常是调度
→
二级：财务没配财务就直接到老板
→
三级：老板终审金额大或财务要求时才有
这笔要走到老板那里吗？
金额达标单笔金额 ≥ 设定的阈值（默认 5000 元） → 财务审完后自动送老板终审。
财务主动送财务觉得有问题，可以点「送老板终审」，不管金额多少。
不用送金额没到阈值，且财务直接通过 → 审批结束。
驳回必须写原因（缺凭证 / 金额与票据不符 / 运单号不符 / 重复上报 / 超过规定期限 / 其他）→ 状态变「已驳回」。
重新提交司机改完再交，按当前配置从头走一遍审批，不会接着上次的进度。
跳过规则：① 自己报的单，跳过自己那一级；② 一级设成"免审"就直送财务；③ 没配财务角色，二级自动顶到老板；④ 同一个人不会在两级里出现两次。
3
财务登记打款财务状态：待打款 / 已通过
进「付款登记」看到所有待付的单
→
填付款信息方式、时间、流水号
→
上传付款凭据截图或回单，最多 5 张
→
确认付款状态变「已打款」
付错了可以「撤销付款」，必须选原因（金额付错 / 重复付款 / 收款人不对 / 账户信息有误 / 其他）→ 这笔回到待付款清单，重新付一次。
批量可以勾选多笔一起登记付款，但单笔 ≥ 5000 元的不能批量，必须逐笔确认。

两个开关决定这条链路走不走

  1. 审批开关（由主账号控制）：全开 / 全关 / 每单自定义。关掉后上报即通过，不产生审批链。
  2. 付款开关：关掉后整个"付款登记"菜单都不出现，费用停在"已通过"。
  3. 两者有依赖：审批关掉，付款也不能用（钱都没审，谈不上付）；但审批开着，付款可以单独关。
  4. 「自定义」模式下，调度可以在建单时单独把这单设成免审。
  5. 改了配置只影响之后提交的单，已经在审的按当时的流程走完。

谁能审、谁能付

  1. 审批：只认当前这一级指定的审批人；老板那一级由主账号兜底。
  2. 付款：只有主账号或角色名里带"财务"的人能登记。
  3. 列表上的"待我审批"只统计轮到我这一级的单，不是全部在审的单。
  4. 审批关掉时，"待我审批"数字直接归零，不显示红点。
  5. 子账号即使有页面权限，也不一定能审 —— 取决于是否被配成审批人。

金额与统计口径

  1. 费用类金额 = 各条明细金额相加，由系统重新算一遍，不信任手填的合计。
  2. 磅单净重 = 毛重 − 皮重，必须毛重 > 皮重。
  3. 超时分钟数 = 实际时间 − 计划时间，实际必须晚于计划。
  4. 费用统计按上报时间归月，不是按审批或打款时间，所以会出现"本月报的单下月才付"。
  5. 环比是和等长的上一段时间比，不是"上个自然月"。

电子围栏与到车提醒

先画圈，再定规矩，最后才会有提醒
三件事：围栏是"圈"，提醒是"规矩"，事件是"结果"。只有前两件都配好了，才会有事件产生。
1
画一个围栏调度 / 运营
选类型装货 / 卸货 / 提醒
→
选形状圆 / 多边形 / 路线 / 行政区
→
在地图上画点选或拖拽
→
起名保存名称不能重复
圆点一个中心，拖动半径（50 米 ~ 50 公里）。厂区、仓库最常用。
多边形连续点几个角、双击结束，至少 3 个点。不规则厂区。
路线画一条线再给个宽度（1~300 米）。管道、专用通道。
行政区直接选省市區。只能看不能改，也无法用来打卡判定。
为什么要先选类型：建单选装货地时只列"装货"类围栏，选卸货地只列"卸货"类，避免选错导致里程和打卡全错。
2
定提醒规矩调度 / 运营
选要盯的围栏只列"提醒"类
→
设超速规则默认 80 km/h
→
设停留规则几次 / 多久 / 多大范围
→
设生效时段默认 05:00–23:00
→
保存覆盖式保存
不选围栏等于全域提醒（所有车都盯），保存前会二次确认。
3
产生提醒事件系统自动
超速车速超过阈值 → 记一段超速。连续超速间隔 5 分钟以上就算新的一段，不合并。
停留车在某个范围内停够时长 → 记一次停留，同时看次数是否超限。
4
查事件、看明细调度 / 运营
按时间 / 车辆筛默认查近期
→
看汇总多少段、多少车、最高速
→
点开明细速度曲线 / 停留轨迹
→
导出给车队做考核
看数顺序：先在「提醒设置」确认规则是开的，再去「提醒事件查询」看结果 —— 规则没配，查什么都是空的。

围栏这几条别踩

  1. 围栏名称同一个客户下不能重名，因为建单选的是"名字"。
  2. 围栏画好之后不能改形状，只能改名和改类型。画错了删掉重画。
  3. 改名会同步到提醒设置里，不会导致提醒失效。
  4. 删围栏时如果云端删除失败，本地仍会删掉，并提示"云端可能残留"。
  5. 三类围栏的颜色是固定的：装货蓝、卸货绿、提醒橙。

提醒能做到什么、不能做什么

  1. 目前只有两种：超速和停留。没有"进出围栏提醒"。
  2. 没有按星期生效、没有指定接收人、没有绑定"只盯某几辆车"。
  3. 子账号只能看不能改。
  4. 事件列表顶部的统计卡是全量统计，不跟着筛选变；导出也是全量，不是当前筛选结果。
  5. 数据缓存 5 分钟，刚改完规则可能不会立刻体现。

档案：客户、货物、车辆、司机

建档一次，建单时自动带出，少填多对
1
客户档案调度 / 客服
建客户名称、负责人、电话、地区
→
上传合同选填，5MB 以内
→
加联系人可以加多个
→
给联系人定角色装货 / 卸货 / 两端都管
两端都管标成"唯一"的联系人，建单时装货和卸货两边都能带出来。
只管一端标"装货"的人只出现在装货侧，标"卸货"的只在卸货侧。
2
货物档案调度 / 商务
建货物名称 + 计量单位
→
加计费规则含税 / 不含税单价
→
选计价方式按公里 / 按吨 / 按趟…
按公里运费 = 里程 × 单价（适合长途）
按数量运费 = 数量 × 单价（按吨/件/箱/车）
按趟 / 人工一口价，或干脆让调度手填
建单时：选中货物 → 带出单位和单价 → 立刻自动算出运费。调度如果手动改了运费，系统就不再自动覆盖。
3
车辆与司机档案车队管理
建车辆车牌、VIN、燃料、所属机构
→
建司机姓名、手机号、所属机构
→
互相绑定车绑司机 / 司机绑车
→
开通小程序账号用手机号当账号
绑定的作用派"车辆"时，系统按这辆车绑定的司机去判断谁能接、谁该看到。绑错了就派不到人。
批量导入车辆、司机都支持 Excel 导入。只要有一行填错，整批都不导入，避免导入一半。

建档时的规矩

  1. 司机姓名和手机号必填，手机号在本公司内不能重复。
  2. 客户名称可以重名，系统只提示不拦（现实中确实有同名公司）。
  3. 车辆的原所属机构不能直接清空，要先换到别的机构。
  4. 车辆和司机的绑定是双向的：在车那边加司机，司机那边也会出现这辆车。
  5. 删除司机时，他的小程序账号一起停用。

带入建单的规矩

  1. 某个角色只有 1 个联系人 → 自动填上；有多个 → 留空让调度自己选。
  2. 带出联系人时，只有对方留了电话才会覆盖发货/收货电话，不会把已填的号码清空。
  3. "唯一"联系人被带到一端后，另一端如果还是空的，会跟着复制过去；另一端已选人就不动。
  4. 档案里没有对应角色的人 → 提示"该客户暂无装货联系人"，不阻断建单。
  5. 货物带了单价但数量为 0 或单价为 0 → 运费不自动算，留空让调度填。

主账号专属系统管理、费用审批设置这两块任何子账号都勾不上，只有主账号能进。
4
司机账号走另一条路车队管理
司机档案里开通账号用手机号当账号
→
司机只能登小程序不能登电脑端
→
只能看到派给自己的单看不到别人的
两个角色别搞混：「调度」是员工，用电脑端；「司机」是运力，用小程序。司机档案里开通的是小程序账号，不是在用户管理里新建一个人。

权限这条线怎么判

  1. 看到菜单，不代表能进页面；能进页面，也不代表能操作。三层依次判断。
  2. 客户开通了哪几个功能模块，就只出现哪几块菜单 —— 直接敲网址也进不去。
  3. 子账号默认继承角色权限，主账号再单独加减。
  4. 主账号永远拥有全部权限，不受勾选影响。
  5. 组织层级越低，看到的数据越少：二级车队账号只看自己车队的人和车。

数据隔离

  1. 每个客户的数据互相看不到，靠"归属账号"隔离。
  2. 管理员身份的单（无归属）所有人可见，但操作时要靠名字唯一性确认归属。
  3. 子账号能看到的范围 = 自己组织 及下级组织。
  4. 客户档案、货物档案也按客户隔离，互相不可见。

实时监控与运营报表

看当下（车在哪）和看过去（跑得怎么样）
1
看当下：车在哪、在干什么调度
选机构左侧组织树
→
看车辆状态行驶 / 静止 / 离线
→
按任务筛在途 / 待装 / 空闲
→
点车看详情位置、任务、司机
→
看轨迹这趟怎么走的
行驶车辆通电且有速度。
静止车辆通电但速度为 0。
离线车辆断电，或定位取不到。
只有车牌是唯一一辆车的运单才能画实时位置。一单派了多辆车（显示"多种""2 辆"）时，地图上不显示轨迹，因为不知道该跟哪一辆。
2
看过去：日 / 周 / 月报车队长 / 运营
选周期日 / 周 / 月 / 自定义
→
选车辆一台或多台
→
看指标里程、电耗/油耗、运行时长
→
导出给甲方或内部考核
查不到数东风平台的能耗数据延迟 1 天，当天和昨天常常查不到，属正常。页面上会提示"改查前 1 天"。
3
看经营：综合报表运营 / 老板
出车日历一个月里哪几天没出车
→
异常车清单电耗高 / 里程低 / 闲置多
→
效率象限谁跑得多又省
→
车队排行Top10
→
车辆矩阵逐日对比
异常判定电耗排在前 15% 偏高、里程不到中位数的 35%、运行占比不到 18% —— 命中任一即进异常清单。
象限分档横轴日均里程、纵轴百公里电耗，取中位数分界 → 高利用低耗（标杆）、高利用高耗、低利用低耗、低利用高耗。
4
看单票：能耗报告与车队报告运营
能耗报告按单车单月出一份报告：日里程与电耗、分路段、驾驶行为、六维评分（能耗/出勤/车速/技巧/路面/车况）、帕累托。
车队运营报告按日/周/月/季/半年/年，看准时率、单公里成本、车辆分档（最省 / 稳 / 偏贵 / 要查 / 样本少）。
准时怎么算：实际用时 ≤ 计划用时 × 1.15 就算准时（留 15% 容差）。

读数前先确认口径

  1. 系统里有三套里程：计划里程（建单时算的）、实际行驶（车辆上报）、里程表读数。报表用的不一定是你以为的那个。
  2. 运单统计里的"在途"是已接单到已到达，不含待接单；车队报告里的"在途"是没完成也没取消，两者不一样。
  3. 平均车速有时是平台给的区间值，有时是逐日平均再平均，长短路混在一起会失真。
  4. 百公里电耗要用实际电耗 ÷ 实际里程算，平台自带的一个汇总字段一直是 0.02，不能用。
  5. 报告里的排名条长度是视觉映射（最短 50%），不代表真实占比。

目前还看不到的

  1. 驾驶行为报表还是占位页，只有入口没有内容。
  2. 充电次数、加油次数、电池电量、充电时长 —— 都还没有。
  3. 能耗报告目前是演示数据，真实取数还没接上。
  4. 车队运营报告没有导出和图表图片，结论只能看页面。

业务规则速查表

被问到"为什么不行"的时候，先在这里找答案
场景规则为什么 / 结果
建单装货地、卸货地必选没地点就算不出计划里程，也做不了打卡判定
承运量合计必须等于货物总量允许 0.01 尾差；否则拆量对不上，结算会扯皮
一个任务只能挂一个货物要拉两种货请建两个任务
计划送达可以早于装货，系统不拦已知缺口，填错了要靠人检查
极简模式强制不做打卡只有两步的单没有"到场"这个概念
接单同一辆车同一时间只能有一条未结束的单防止一辆车被派两个活
同一个司机同一时间只能有一条未结束的单防止一个人被派两个活
待接单不算占用还没接的单可以自由改派
派车队的单不能拒不是派给某个人的，不接就放着
常驻的趟次不能拒拒了额度就浪费
改派只有待接单 / 待重新指派能改已接单的换人要先把原单处理掉
改完状态回到待接单否则新司机在任务清单里看不到
打卡装车完成必须在装货围栏内用车辆定位判断，不是手机定位
确认到达必须在卸货围栏内同上
围栏画成"行政区"时不做校验系统判断不了，放行并留说明
多车单一律不校验不知道该跟哪辆车
常驻次数额度是所有司机共享的先到先得，后到的提示"额度已用完"
额度用完不会立刻结束等最后一趟跑完才收口
有趟次在跑时不能暂停 / 结束 / 删先把在跑的跑完
趟次没有计划时间临时排的，所以不显示计划 vs 实际
分车混入车队指派就不是分车承运按普通单处理，车牌显示"多种"
全部完成或 完成+拒单 才收尾不可能再等了
费用必须已接单才能上报待接单 / 待重新指派 / 已取消都不行
只有 4 类钱款计入总额单据类只记笔数，避免总额虚高
金额 ≥ 5000 要老板终审阈值可配，配 0 表示不按金额触发
单笔 ≥ 5000 不能批量审批大额必须逐笔看
驳回后重提从头走审批不接着上次的进度
付款只有主账号或财务能登记其它人看不到"付款登记"菜单
审批关了，付款也不能用钱没审过，谈不上付；但付款可以单独关
撤销后回到待付款重新付一次，原付款信息保留可查
权限系统管理 / 费用审批设置仅主账号子账号任何角色都勾不上
司机不能登电脑端司机用小程序，员工用电脑端
没开通的功能模块，敲网址也进不去菜单不显示 + 页面拦住
组织有下级组织的不能删先把子组织和车辆挪走
报表能耗数据延迟 1 天当天/昨天查不到属正常
多车单不画实时轨迹不知道该跟哪辆车
