架构文档

车队运输管理系统 · 整体架构全景图

面向车辆运输、运单调度、费用结算与车队资产的 SaaS 系统，现运行于腾讯云 CloudBase（Serverless 形态）。 本文按七层结构拆解真实代码，逐层说明职责、组件与技术栈，并标注跨云迁移的影响面。

版本 v1.0 日期 2026-11-24 代码基线 my-cd 主分支 运行形态 Serverless（CloudBase） 规模基线 2,000 台车 / 20 客户

核心数据流

四条最典型的链路，展示各层之间实际的协议与跳数。

Web 查询列表 2 跳 · 最快

绝大多数列表页走这条，不经过云函数

浏览器Vue 页面→ app.rdb()supabase.js→ PostgRESTHTTP + anon key→ PostgreSQLSQL 执行

Web 执行运单动作 3 跳

涉及状态机推进，必须由云端计算动作链

浏览器运单详情→ HTTP 网关tcloudbase.com→ waybill-action云函数→ node-sdk写库 + 留痕→ PostgreSQLwaybills

小程序司机登录 3 跳 · 内网

走微信内网通道，不经过公网，首包更快

小程序账号密码→ callFunction微信内网→ login-by-account校验 + 签发→ user_sessions会话落库

全图监控展示车辆位置 4 跳 · 最慢

每条链路都要过东风接口，因此做了 25s 轨迹缓存

FullMap地图页面→ dongfeng-lostlocation云函数→ 东风开放平台8s 超时→ 逆地理编码地址缓存→ 高德渲染marker
04

关键约束

这些不是风格偏好，是踩过坑之后形成的硬规则。迁移时若忽略，会以"查询返回空""数据静默错误"的形式复现。

约束内容忽略后的现象
Web 禁 callFunction 前端一律走 HTTP 网关，不走 app.callFunction EXCEED_AUTHORITY 匿名登录态无调用权限
新表必须带授权段 GRANT 给 anon / authenticated + pg_notify 重载 能查但 0 条，写入直接被拒
整数主键 organizations.id / customers.id 是 int，引用表用 text 关联查询类型不匹配，静默返回空
字段白名单 写 vehicles 前按 VEHICLE_COLUMNS 挑字段 42703 整页报错（74 列的 waybills 尤甚）
权限双写 菜单条件渲染必须 isMaster || hasPerm(key) 主账号看到空壳分组，误以为功能丢了
动作链唯一权威 状态推进由云函数 actions[] 决定，前端不推断 前后端状态不一致，运单卡在中间态
常驻任务是一单 一个组号只占一行，第 N 趟只能由司机端"接一趟"产生 重复计数、费用按趟重复合计
时区显式声明 定时任务与"当天"统计必须按 Asia/Shanghai 统计口径偏 8 小时，且不报错
05

迁移影响面

按层评估迁往标准云架构（ECS + RDS + OSS）的改造性质。结论：真正的重活在 L5 数据访问层，不在 L4 业务逻辑。

层现状目标形态改造性质说明
L1Vue SPA 静态包不变 零改动 构建产物直接由 Nginx 托管；可顺带删掉 199KB 的 CloudBase SDK
L2CloudBase 托管 + HTTP 网关Nginx + CDN + 自建 API 域名 配置重做 需重新接入备案、签发证书；小程序须改合法域名并重新提审
L3匿名登录 + 业务会话自建 JWT + 会话表 结构变更 匿名登录无替代品；这是全站地基，改错则白屏。建议与 P0 改造合并
L430 个云函数单 Node 服务 30 个路由 容器适配 业务逻辑不动，改入口签名与 event 解析；顺便消灭 4 份重复的运单查询条件
L5前端直连 PostgREST统一 API + pg 连接池 重写 最大工作量。全站数十处 supabase.from() 改为 HTTP；连接池需单例
L6CloudBase PG 共享版RDS for PostgreSQL 数据直搬 pg_dump 直导；注意序列 setval 与授权段重写。别按"业务/位置"分两个库
L7高德 / 东风 / AI / 微信不变 零改动 第三方接口与云厂商无关，仅需确认出网 IP 白名单
一句话总结：这套系统的业务价值集中在 L1（界面）与 L4（业务规则），而这两层迁云几乎不用改； 真正的成本在 L5 那薄薄一层「前端直接连数据库」——它现在是优势（少写一套 API），迁移时是负债（必须补一套）。
推荐部署形态：单台 ECS 4C8G 全包（Nginx + Node API + 采集器 + 定时任务）+ RDS 2C4G + OSS + CDN，月成本约 1,000–1,450 元。
