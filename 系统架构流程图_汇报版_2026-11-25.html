部署方式

前端不部署到服务器，而是上传到云厂商的静态托管服务，由 CDN 就近分发。一条命令完成：

npm run build && npx tcb hosting deploy dist

关键约束：Web 端禁用 app.callFunction —— 匿名登录态会触发权限不足。因此 Web 与小程序走两条不同通道，同一个云函数需同时兼容两种入参格式。

应用服务层 · 云函数

全部业务规则在此计算
30 个 9 个领域
云函数是什么（Serverless / FaaS）

云函数是函数即服务（Function as a Service）。开发者的交付物不是一个服务进程，而是一个函数： 上传代码后由平台托管，有请求时才拉起实例执行，执行完释放；没有请求时实例数为零。

它与传统服务器最根本的差别在于计费与运维模型：不需要购买、安装、补丁、扩容任何服务器， 按「调用次数 + 执行时长」计费，无人访问时成本为零。

触发方式HTTP 请求 / 定时器
运行时长单次有上限，不能常驻
状态无状态，实例随时回收
首次调用冷启动，需预热
运单域4 个函数 费用域2 个 车辆域6 个 车联网域4 个 地理围栏域3 个 组织认证域4 个 统计域2 个 AI 域2 个 文件通知域2 个
部署方式

每个函数是独立的部署单元：各自打包（含自身依赖）、各自配置环境变量、各自上线。修改任一函数都需单独重新部署。

另有 2 个定时任务通过 cron 表达式触发（证照巡检每小时、行为统计每日 01:30）。

架构特点：30 个函数之间几乎不互相调用 —— 它们共享的是数据库，不是彼此的接口。真实跨函数调用仅 1 处。
由此带来的代价：同一张表的查询条件在 4 个函数里各写一遍，改一个字段要改 4 处、部署 4 次。这是后续优化的主要方向。

数据访问层

查询构造、字段容错、文件签名
3 种通道
前端直连app.rdb() 云函数访问node-sdk COS 签名signPut / signGet
为什么前端能直接连数据库

因为所用的数据库环境提供了一层 PostgREST 中间层 —— 它把 PostgreSQL 的表暴露成 HTTP 接口， 前端通过 HTTP 发出查询，由中间层转成 SQL 执行。这层同时提供行级权限（RLS）与匿名角色控制。

所以前端代码里看不到连接字符串，只有 app.rdb() 这样的 SDK 调用； 但本质仍是前端直接读写数据库，不经过业务服务。

字段容错是刚需：运单表有 74 列且无更新时间戳，写入前必须按白名单挑字段，否则整页报错。
文件不走数据库：凭证图存对象存储，业务表只存键名与大小，展示时临时签名链接（缓存 50 分钟）。

数据层 · 数据库与存储

结构化数据与文件对象
PostgreSQL 30 表 + 1 视图
数据库类型

关系型数据库 · PostgreSQL，由云厂商以托管服务形式提供（共享版实例，非独享）。

类型关系型（SQL）
版本形态托管 · 共享版
访问方式HTTP（PostgREST）
权限模型行级权限 RLS
数据规模30 张业务表
特殊对象1 个 40 列宽表视图

选型上重度使用了 PostgreSQL 的特有能力：JSONB 存非结构化字段、数组存多值属性、 窗口函数做排名统计、视图做宽表导出。这些是迁移时最需要留意的部分。

对象存储

对象存储（COS）存放凭证照片与报表图片。业务表只保存 {键名, 文件名, 大小}，不保存访问地址 —— 这是迁移时最省事的一处，换存储桶无需回填任何数据。

两条硬规则：新建表必须显式授予匿名角色读写权限并刷新 schema 缓存，否则表现为「查询返回 0 条、写入被拒」；组织与客户主键是整数，关联表须用文本类型承接。
06

外部集成层

第三方服务对接，与云厂商无关
4 类接口
高德地图渲染 / 地理编码 东风车联网位置 / 轨迹 / 能耗 AI 模型ai-gateway 代理 微信开放能力订阅消息
实时位置接口：一次只能查一台车，单次超时 8 秒，无数据时向前回退最多 3 次请求 —— 这决定了采集频率与并发设计。
能耗接口：只能 POST 且参数必须放在 URL 查询串；数据有 1 天延迟，当天只能返回空值。
迁移友好：这一层全部是公网 HTTPS 调用，换云厂商零改动，只需确认出口 IP 是否需要加入对方白名单。

双层授权模型

模块可用性由两个开关共同决定：运营授权（服务商置位，客户不可改）与 客户启用（客户自行开关）。 客户只能调整后者，且必须在前者为真的前提下才生效。

认证是地基：Web 端启动即执行匿名登录，失败则全站无法取数。跨云迁移时这一层无同等替代品，必须替换为自建令牌方案。

04 · 下一步
标准云架构对照

若迁往标准云架构（云主机 + 托管数据库 + 对象存储），各环节的改造性质。

环节 现状 目标形态 改造性质 说明
① 终端 Vue 3 静态包 不变 零改动 由 Web 服务器托管；可顺带移除已不再需要的云 SDK（约 199KB）
② 接入 云托管 + 云网关 Nginx + CDN + 自有域名 配置重做 需重新接入备案、签发证书；小程序须改合法域名并重新提审
③ 云函数 30 个独立函数 单服务 30 个路由 容器适配 业务逻辑不动，改入口与参数解析；顺带消除重复的查询条件
④ 数据访问 前端直连 HTTP 接口 统一 API + 连接池 重写 工作量最大。全站调用点改为 HTTP，需引入单例连接池
⑤ 数据库 托管 PostgreSQL 共享版 托管 PostgreSQL 独享版 数据直搬 导出导入即可；注意序列当前值与授权语句重写
⑥ 外部集成 高德 / 东风 / AI / 微信 不变 零改动 公网接口与云厂商无关，仅需确认出口 IP 白名单
⑦ 横切 云开发匿名登录 自建令牌 + 会话表 结构变更 无同等替代品，是全站地基，建议与其它改造合并为一次
