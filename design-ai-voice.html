01

音波图标规范

两端共用一套

现在输入栏用的是 🎤 emoji —— 系统里其它图标全是细线 SVG，emoji 一放进去就跳出色系、还随系统字体变形。 改成五根圆角细柱组成的音波：静止时是「声音」的静态形状，录音时柱高跟着音量走。 同一个图形，Web 只做静态，小程序做动态。

空闲 · 静止
#475569 / 柱高 5·10·15·10·5
按住 · 实心红
#C8102E 底 + 白柱
不可用 / 占位
#C3CCD9 / 整体 0.55 透明
为什么要改成音波
① 和系统里 24×24 细线图标同一套语言，不再有 emoji 色差；
② 同一个图形能表达两种状态：静止=可说话，跳动=正在听，不用换成两个图标；
③ 柱高天然是「音量」的隐喻，用户一眼知道「它在听我」；
④ 尺寸极小（18×16），放在 30px 按钮里仍清晰。
柱数 5 柱宽 2px 间距 2px 圆角 2px（全圆头） 整体 18×16px 颜色 currentColor（继承按钮，暗色主题自动跟随）

A动效只有两处

  • 录音态：柱高按实时音量变化，节流 60ms、线性插值 120ms —— 不做 60fps 全速刷新，避免「抖」
  • 入场一次：面板打开后 2 秒内，五根柱依次抬升一次（0→1→0，各错开 60ms），之后永久静止

B明确不做

  • 不做无限循环的「呼吸」动画 —— 面板常驻，一直动会分心
  • 不做扫描光条、扩散波纹、来回扫的渐变
  • 不做快闪（<0.5s 一轮）—— 用户明确反感

C可复制的样式

柱高用 :nth-child 定死，录音时改 --v：

/* 18×16 音波 */
.wave{display:flex;align-items:center;
  gap:2px;height:16px;color:currentColor}
.wave i{width:2px;border-radius:2px;
  background:currentColor;
  height:calc(var(--b) * var(--v,1))}
/* --b 基准高 5/10/15/10/5
   --v 音量 0~1，录音时由 JS 逐根写 */

A为什么不做成「点了没反应」

点了没反应 = 坏了。所以给三件事：一行说明（告诉你为什么） + 焦点跳转（给你出口） + 按钮按下去变灰（告诉你它现在不可用），3.5 秒后自己收起，不打扰。

B提示文案备选

  • 推荐：语音输入在小程序端可用；这里直接打字更快
  • 短版：语音请在小程序里说，Web 端先打字
  • 语气太硬不用：「Web 端暂不支持语音」——像错误提示

C别动的地方

  • 不改 textarea 的自增高逻辑（autoGrow）与 Enter 发送
  • 按钮放在 textarea 左侧，与 01 稿一致；右侧留给发送键
  • 未连接（!hasToken）时按钮一并置灰，不给「去小程序」的误导

D预留 Web 接 ASR 的位置

点击处理统一走 onMicTap()，里面现在只做提示；将来接腾讯云时，把这一处换成开始录音即可，版式与状态类（.mic.rec）已备好。

A五个决定（2026-11-27 改为微信手势）

  • 语音 / 键盘一键切换：左侧图标，键盘模式显示音波、语音模式显示键盘；切到语音自动收键盘，切回键盘时若还停在确认态先把文本回填
  • 按住说话 / 松手结束：与微信一致，司机和调度不用学第二套操作。最早那版是「点一下开始」，实际用下来大家习惯按住 —— 已改
  • 上滑越过 56px 松手取消：浮层整体转黑、长条也转黑底白字，文案变「松开取消」
  • 浮层向上展开，不替换输入栏：按住的节点一旦被销毁，touchend 就收不到、录音停不下来（实现时踩实了）
  • 第一次要授权：未授权时按下先弹授权，回来后请再按一次 —— 比「按住没反应」可解释
  • 实时字幕用打字机追赶：插件回调是整句来的（实测 1~2s 一次），一次性替换会「蹦一大段」；改成每 70ms 补 1~3 字，且只显示最新 40 字（否则画面永远停在句首像卡死）
  • 松手直接发送（用户 2026-11-27 定）：与微信一致，不再停确认卡；想回到「先确认再发」把 VOICE_AUTO_SEND 置 false，确认卡分支保留

B为什么用 chips 而不是框内高亮

小程序 textarea 里做不到内联高亮（没有 contenteditable）。所以改成：文本可自由编辑，下方用 chips 列出「我识别到的实体」，低置信度打 ? 并用琥珀色 —— 用户扫一眼就知道该核对哪几处，比染色更实用。

C三种出口，别让人卡住

  • 确认态接管输入区：原输入栏暂时隐藏 —— 两个输入框同时在场，用户不知道该改哪个
  • 上滑取消：越过 56px 浮层转黑、提示变「松开取消」，松手即丢弃，不留草稿
  • 重录：确认态一点回到录音，已识别文本保留（重录失败不至于全丢）
  • ✕ / 继续打字：确认态关掉，文本回填到输入框而不是丢掉

D时长与打断

  • 单次上限 60s（插件限制）；到 60s 自动停止并转写，不丢已识别内容
  • 切后台 / 来电 → 立即停止并保留文本，回到前台进确认态
  • 面板被关掉 → 停止录音，不保留（避免后台偷偷占用麦克风）
  • 手指滑出按钮不会中断：事件跟着按下时的节点走，只要不松手就继续录

05

技术实现

端上直连，无云函数

微信同声传译是小程序插件，识别在端上 + 微信侧完成，我们的服务器不参与，也不需要任何密钥。 所以这次不新增云函数，改动只在小程序工程内（不影响已部署的 ai-gateway）。

① 声明插件 · src/manifest.json 
// mp-weixin 节点下追加（uni-app 会写进 app.json）
"mp-weixin": {
  "plugins": {
    "WechatSI": {
      "version": "0.3.6",   // 以插件市场当前版本为准
      "provider": "wx069ba97219f66d99"
    }
  }
}
② 封装 · src/utils/voice.js 
// 只在微信端引入，其它端整文件 return no-op
let mgr = null
function ensure() {
  // #ifdef MP-WEIXIN
  if (!mgr) {
    const si = requirePlugin('WechatSI')
    mgr = si.getRecordRecognitionManager()
  }
  // #endif
  return mgr
}

export function startVoice({ onLive, onDone, onFail }) {
  const m = ensure()
  if (!m) return onFail({ kind: 'unsupported' })
  m.onRecognize = r => onLive(r.result || '')
  m.onStop      = r => onDone(r.result || '')
  m.onError     = e => onFail({ kind: mapErr(e), raw: e })
  m.start({ duration: 60000, lang: 'zh_CN' })
}

export function stopVoice() { ensure()?.stop() }
③ 权限预检（不要一上来就 start） 
async function ensurePerm() {
  const s = await wx.getSetting()
  if (s.authSetting['scope.record'] === false) {
    // 已明确拒绝过 → 只能引导去设置页
    return { ok: false, denied: true }
  }
  try { await wx.authorize({ scope: 'scope.record' })
    return { ok: true } }
  catch { return { ok: false, denied: true } }
}
授权成功直接进入录音，不要「已授权，请再点一次」。
④ 音波驱动（音量 → 柱高） 
// 60ms 节流，120ms 线性插值；不要逐帧 setData
let last = 0
m.onFrameRecorded = function (res) {
  const now = Date.now()
  if (now - last < 60) return
  last = now
  const v = rms(res.frameBuffer)   // 0~1
  setBars(v)
}
// setBars 只改 12 根柱的 style.height
// 静音时收到基线，不再抖动
⚠️ 插件本身不给音量，需要另一路 RecorderManager 才能拿 onFrameRecorded； 若要省事，可退化为固定节奏的柔和波动（1.8s 一轮、幅度 30%），观感差别不大。
⑤ 手势（按住 / 上滑取消） 
// touchstart 立即开录（权限已就绪时），move 判阈值，touchend 收口
function onMicTouchStart(e) {
  holding = true
  touchStartY = e.touches[0].clientY
  if (!permReady.value) { /* 先授权，回来提示「再按一次」 */ }
  else beginRecording()
}

function onMicTouchMove(e) {
  // 上滑超过 56px → 取消态；回滑自动恢复
  willCancel.value = touchStartY - e.touches[0].clientY > 56
}

function onMicTouchEnd() {
  holding = false
  if (willCancel.value) { cancelVoice(); resetVoice() }  // 丢弃
  else stopVoice()                                     // 进确认态
}
⚠️ 承载 touch 的节点在录音期间不能被 v-if 掉 —— 一旦输入栏被替换，按住的节点销毁，touchend 收不到，录音永远停不下来。所以浮层用 absolute 向上展开，输入栏保留（只压暗）。
⚠️ 必须 catchtouchmove（.stop.prevent），否则手指上滑会带着消息列表一起滚。
⚠️ 插件 stop() 后可能补一个迟到的 onError，失败处理里先判状态是否还是 recording，否则取消后弹莫名报错。
异常现象判定界面处理
用户拒绝过授权authSetting.record === false条内提示 + 「去开启」→ wx.openSetting；不再弹系统框
录音初始化失败 / 被占用onError retcode 非 0提示「麦克风被占用，稍后再试」+ 重录；不进入确认态
无网络设备离线 / 识别超时提示「没网，先打字或稍后重试」；已识别的半句保留到输入框
一句都没识别到result 为空串提示「没听清，再说一遍？」+ 大号重录按钮
环境太吵 / 说了方言result 长度 < 4 字同上，但文案改为「周围太吵？靠近点说」
插件未安装（旧版本包）requirePlugin 抛错try/catch 兜住，麦克风按钮直接不渲染，输入框照常
