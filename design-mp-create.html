A为什么能直接复用

  • 草稿 JSON 两端同构：tasks[] / cargoList[] / assignList[] / transportMode，小程序任务模型字段一一对得上（pickupLocation→pickup、deliveryTime→planTime）。
  • 建单页已有 seed 通道：adminCreateSeed + options.mode。加一个 mode=ai 就能接草稿，不用另造一套。
  • ai-gateway 的 main(event) 直接吃事件体，所以 redraft / resolve 用 wx.cloud.callFunction 传 action 即可，无需改后端。
  • 小程序没有 SVG：图表卡继续用后端同源的 table 降级，草稿卡改成原生渲染（这才是重点）。

B建单页要改的六处

现状改法
必填项没标记，提交只弹一句 toast字段加 *；提交时滚到第一个缺项并标红
切页 / 返回就丢填写本地暂存，下次进入问「继续上次填写？」
没有客户字段（云函数也不写）行程区加「客户」行，可手填；有档案就一起写 id
20+ 行字段一直铺开，找东西要滚很久联系人/电话默认折叠成一行，点开才展
提交前后没有总览底部改「提交前确认」半屏（屏 3）
缺项只在 toast 里说一句底部常驻「还差 N 项 · 货物 · 车辆」，填完自动消失

C三个需要你定的选项

  • 草稿卡形态：A 原生全量卡（如屏 1）／B 紧凑 6 行 + 展开／C 保持表格只加按钮。
  • 客户字段：A 只手填名字（轻，云函数加 2 个字段）／B 手填 + 从客户档案选（中）／C 不做。
  • 计划里程：A 继续留空／B 小程序也调高德算一次（+0.3 天，运单详情能显示里程）。
