语音输入

司机场景最高频

司机在车上、调度手上拿着单子，打字是最慢的一环。三态：空闲 → 录音中 → 转写确认。 关键约束：转写结果必须落在可编辑的输入框里，不能识别完直接发出去 —— 地名和数字识别错一次，后面全错。

A交互为什么这么定

  • 点一下开始 / 再点结束，不用按住——司机单手、戴手套按住容易滑
  • 不做「上滑取消」（会被页面滚动吃掉），改成明确的「↺ 重录」
  • 波形只用 3px 细柱 + 低透明度，符合整体「细实线 + 不闪」的调性
  • 识别到的地名 / 车牌 / 数量加底色高亮，让用户知道「这几处最容易错」

BASR 选型（要花钱，先定）

  • 腾讯云一句话识别：和现有云资源同厂，按次计费，1 分钟内短句最合适
  • 微信同声传译插件：小程序端零密钥、免费额度，但只能在小程序用
  • 建议：小程序用同声传译、Web 用腾讯云，两条通道各自最省

C实现要点

  • 新增云函数 ai-asr（Web 端中转，藏住 SecretKey）；小程序直连插件不经过它
  • 录音用 RecorderManager，采样 16k / 单声道 / mp3，控制在 200KB 内
  • 识别失败要能退：给「还是打字吧」的出口，不要卡在录音态

截图 / 单据识别

复用现有 OCR

调度手上常有别人发来的派单截图、纸质单据。现在只能自己照着敲一遍。 目标是「贴一张图 → 认成草稿字段 → 缺的再问」。

A三种入口，优先级从高到低

  • 直接粘贴（⌘V / Ctrl+V）：最快，调度本来就在截别人的图
  • 拖拽进面板：拖到助手面板任意位置即可
  • 点 ⌗ 选文件：兜底，文件选择器

B识别结果的三个规矩

  • 只填空白项：已确认字段绝不覆盖，避免「手改过的被机器改回去」
  • 低置信度要点名：置信 <0.7 的字段标琥珀色，并在回答里说明「可能是 A 或 B」
  • 图片本身不存库：只留识别出的文本，原图当天丢弃（涉及客户单号隐私）

C用哪个 OCR

  • 现成有 report-ocr（费用票据专用，输出金额/日期/发票号），字段对不上
  • 建议新写 ai-ocr 走通用文字识别 + 结构化抽取：OCR 出文本，模型只做「字段映射」，数值仍由程序校验
  • 小程序端调 chooseMedia 拿图 → 传云函数 → 同一条链路

图表与明细合成一张卡

改动最小 · 立竿见影

现在问「这个月能耗怎么样」会出两张卡：一张明细表、一张图，手机上要滑两屏才能看完。 后端本来就同时给了 chart 和 table，前端合成一张即可，不用改接口。

A为什么合并

  • 图给结论、表给核对，本来就是同一件事的两个视图，拆成两张卡反而像两条回答
  • 手机上省一屏；Web 端也少了「滚下去再看表」
  • 明细默认折叠，需要核对时点开，不占版面

B实现

  • 后端不动：render_chart 已经把 table 一并下发
  • 前端：chart 卡内部渲染 card.table，折叠态用 max-height:0 + overflow:hidden
  • 同时不再单独推 table 卡（后端 toCards 里判断：同一轮有 chart 就跳过对应 table）
  • 柱高按 min~max 映射（不是 0 基线）—— 58.5 和 66.4 差 13%，从 0 起画会变成六根等高柱，趋势就没了

成本与配额可见

运营侧 · 防超支

现在配额是 60 次/时、800 次/日，但用户和运营都看不到用了多少，超了只会在下一次提问时被拒。 目标：用之前知道还剩多少，接近上限提前说。

A三个层级

  • 个人：今日已用 / 剩余（面板底部小字，不打扰）
  • 租户：「我的」页一张卡：今日、本月 token、平均耗时、Top 3 提问类型
  • 运营：每周一自动汇总一封（站内 + 订阅消息），列出各租户用量与异常账号

B数据从哪来

  • ai_assistant_logs 已在写：account / tenant / intent / tokens / latency / 是否命中缓存
  • 按天聚合即可，不需要新表；周报用定时触发器（已有 vehicleReminderCron 那套）
  • ⚠️ 日志里不存提问原文和手机号，只存 intent 与工具名

C先做哪一半

建议先做个人 + 租户（读日志即可，0.5 天），周报可以后补 —— 没有可视化之前，周报没人看。
