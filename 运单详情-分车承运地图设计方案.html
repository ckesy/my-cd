运单详情 ·「一货多车」的地图展示 — 设计方案（3 版）

场景：一个运单、一种货物派给多个司机 / 多车（每人各拉一部分）。现在「物流状态」页已经能按趟列卡片， 但**地图只画得出一辆车**（一辆车一条轨迹：按车牌查东风定位 + 规划路线）。 下面给 3 版布局，目标是「**在地图上能同时看到两台车**」，同时不破坏现有单车页面的观感。
⚠️ 本文只是设计方案，线上代码未改动。灰色网格块代表地图，彩色折线代表车辆轨迹。

三版对比与推荐

维度方案 A 一图叠多车方案 B 一车一卡方案 C 一图 + 车辆 tab
「看到两台车」 最直接，同屏对比 不行（分成两张图） 默认「全部」就能看到
单车细节（节点时间轴） 要额外点卡片聚焦 天然分开，各自完整 切 tab 即现有完整视图
车多时（≥4） 轨迹互相压线 一直整齐，但页面很长 聚焦单车，天然不挤
改动量 中（地图叠加 + 联动高亮 + 卡片） 小（把现有地图块复制 N 份） 中偏小（多一层 tab + 叠加态）
与现有页面的一致性 新形态（要重新定视觉） 最高（就是现在这块乘 N） 最高（单车视图原样保留）
建议：方案 C 为骨架，把方案 A 的叠加态作为默认的「全部」页签。 理由：一进页面就满足「地图上看到两台车」，要看单车就走既有视图（进度双条 + 节点时间轴不用重做）， 而且 1 辆车时不出现 tab、与现在完全一致 —— 改动最少、回退最容易。 A 里那套「点卡片聚焦高亮某辆车」作为「全部」页签里的增强交互，随 C 一起做。

落地要点（无论选哪版都要先定）

  • 数据来源：一辆车一条轨迹 —— 现在是按车牌查「东风定位 + 规划路线」算一条；多车就是并行查 N 次 （Promise.all，2~3 辆无压力；≥5 辆建议加并发上限 + 缓存，切 tab 不重复查）。
  • 状态对应：未接单 / 待装车 → 只画装货点（无轨迹）；在途 → 轨迹 + 当前位置 marker； 已完成 → 完整轨迹（描边变灰或转绿）。
  • 颜色规范：按指派顺序固定取色（红 → 蓝 → 青 → 紫），同一辆车在轨迹、marker、卡片、图例里用同一色； 红只给第一辆（品牌红），避免与「异常/超速」告警色打架。
  • 配色与地图合规：沿用现有高德底图与已有标记图标；不新增外部地图源。
  • 对齐现有信息：卡片上的「承运数量」用该趟的 carryQuantity、 顶部聚合用「已完成 x/N · 承运合计 a/b」——和列表页、当前按趟卡片同一口径。
  • 降级：只有 1 趟时全部退回现在的单车视图；某辆车没有定位数据时该卡片显示「暂无定位」而不是空白地图。
  • 命名：界面上**不要出现「子母车」**这类业务词（不一定就是子母车），统一叫「分车承运 / 共 N 趟」。
